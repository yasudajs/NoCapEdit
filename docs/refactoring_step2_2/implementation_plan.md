# ステップ 2.2: `core/fileSystem.js` のリファクタリング

## 目的
マスタープランにおいて、ステップ2.2の目標は「`saveTabIfDirty` および `triggerManualSave` 内部のタイムスタンプ処理を `generateTimestamp()` の呼び出しに置き換える」ことでした。しかし、この作業は**前回のステップ2.1で先行して同時に実施・完了**しております。

そのため、今回のステップ2.2では、`fileSystem.js` 内に残っているもう一つの「冗長なハードコード処理」を共通関数に置き換え、フェーズ2（フロントエンドの冗長コード排除）を完全に完了させることを目的とします。

## 提案する変更内容

### [MODIFY] `src/dist/js/core/fileSystem.js`
1. **タブID生成ロジックの共通化**
   - ファイル冒頭のインポートに `generateTabId` を追加します（`../utils/helpers.js` から）。
   - `openExistingFile` 関数内（314行目付近）で、新規タブオブジェクトを作成する際の `id` 生成処理が直接記述されています。
     ```javascript
     // 変更前
     id: 'tab-' + Date.now().toString(36) + '-' + Math.random().toString(36).slice(2, 8),
     ```
     これを、すでに用意されている共通関数に置き換えます。
     ```javascript
     // 変更後
     id: generateTabId(),
     ```

これにより、`fileSystem.js` 内の日時やランダム文字列に依存するハードコード処理が一掃され、コードの再利用性と可読性が向上します。
