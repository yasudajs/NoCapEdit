# アーキテクチャ ドキュメント作成と spec.md 整理の実装計画

リファクタリングが進みファイル数が増加してきたことに対応するため、システム全体のファイル構成・役割分担・内部設計方針をまとめた `ARCHITECTURE.md` を新設します。また、現在 `spec.md` に記載されている「内部設計」に関する記述を新設する `ARCHITECTURE.md` に移設し、各ドキュメントの役割（仕様、開発手順、内部設計）を明確に分離します。

## User Review Required
- `ARCHITECTURE.md` にまとめるファイル構成の分類や役割分担について、認識の齟齬がないか確認をお願いします。
- 移設対象の選定について問題がないか確認をお願いします。

## Proposed Changes

### ドキュメントの新規作成

#### [NEW] `docs/ARCHITECTURE.md`
以下の構成でシステムのアーキテクチャとファイルの役割分担を定義します。

1. **システムアーキテクチャ概要**
   - Tauri を用いた Rust (バックエンド) と JavaScript/HTML (フロントエンド) の連携モデルの解説。
2. **ディレクトリ構成とファイルの役割**
   - **フロントエンド (`src/dist/js/`)**
     - `core/`: 状態管理 (`state.js`)、ファイル・設定管理 (`fileSystem.js`, `settingsManager.js`)、Tauri APIラッパー (`tauri.js`) など、ビジネスロジックを担当。DOM操作は行わない。
     - `ui/`: タブ制御 (`tabs.js`)、エディタ制御 (`editor.js`)、設定UI (`settings.js`)、テーマ適用 (`theme.js`)、ショートカット (`shortcuts.js`)、ダイアログ (`dialogs.js`) など、DOM操作・イベントリスナーを担当。
     - `utils/`: 汎用ヘルパー関数 (`helpers.js`)。
     - `main.js`: エントリポイント。初期化と各モジュールの結合。
   - **バックエンド (`src/`)**
     - `main.rs`: エントリポイント。Tauriの初期化とプラグイン登録。
     - `commands.rs`: フロントエンドから呼び出されるTauriコマンド群。
     - `settings.rs`: アプリ設定の読み書き・管理。
     - `instance.rs`: 多重起動防止や単一インスタンス通信の管理。
     - `theme.rs`: Windowsネイティブのテーマ（ダーク/ライト）制御。
     - `cli.rs`: CLI引数処理。
3. **技術方針・設計詳細（`spec.md` から移設）**
   - **多言語対応 (i18n)**: フロントエンド表示テキストの `i18n.js` による一元管理方針。
   - **ウィンドウ表示制御**: アプリ起動時のガタつき・チラつき（FOUC）防止のための、初期非表示 (`visible: false`) とフロントエンド初期化完了後の `show` 呼び出しフロー。

### ドキュメントの修正

#### [MODIFY] `docs/spec.md`
- **「3.2 開発技術」の整理**:
  - 「多言語対応 (i18n)」および「コードのモジュール構造」の具体的な実装方針の記述を削除し、「内部アーキテクチャやファイル構成、多言語化（i18n）等の実装方針の詳細は `ARCHITECTURE.md` を参照すること。」という案内を追記。
- **「3.3 ウィンドウ表示制御（起動時ガタつき防止）」の整理**:
  - 詳細なフロー（`visible: false` や `show` 呼び出し）の記述を削除し、実装設計方針として `ARCHITECTURE.md` に移譲する旨を記載。（※製品仕様としては「起動時にチラつきがないこと」のみ概要として残す）

#### [MODIFY] `docs/DEVELOPMENT.md`
- 「📄 仕様詳細」のセクションなどに、内部設計やファイルの役割分担を知るための資料として `ARCHITECTURE.md` へのリンクを追記。
