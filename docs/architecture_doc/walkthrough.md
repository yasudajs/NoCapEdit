# ドキュメント整理とARCHITECTURE.md 新設に関するウォークスルー

## 実装内容
リファクタリングによるファイル数増加に伴い、内部設計やディレクトリの役割分担を明確化するためのドキュメント整理を行いました。本作業はドキュメントの更新のみであり、ソースコードの変更は含みません。

1. **`ARCHITECTURE.md` の新設**
   - NoCapEdit のシステムアーキテクチャ（Tauri, Rust, JS）、ディレクトリ構成、および各ファイルの役割分担を定義するドキュメントを作成しました。
   - `src/dist/js/` 配下の `core/`, `ui/`, `utils/` 等の詳細な責務を明記しました。
2. **`spec.md` の整理と移設**
   - `spec.md` の「3.2 開発技術」に記載されていた「多言語対応 (i18n)」および「コードのモジュール構造」に関する詳細な実装方針を `ARCHITECTURE.md` に移設しました。
   - 「3.3 ウィンドウ表示制御」におけるフロントエンドとバックエンド間の通信フローや初期表示制御の実装詳細を `ARCHITECTURE.md` に移譲し、製品仕様としての記述のみを残しました。
3. **`DEVELOPMENT.md` の更新**
   - 開発者が内部設計を把握できるように、ドキュメントに `ARCHITECTURE.md` へのリンクを追記しました。

## 確認事項
- `ARCHITECTURE.md` にフロントエンドとバックエンドの役割が整理されていることを確認。
- `spec.md` から実装詳細の過剰な記述が除かれ、仕様書としての役割が明確化されたことを確認。
- リンク切れなどの整合性に問題がないことを確認。
