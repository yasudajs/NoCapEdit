# 不可視文字プラグインの長い行描画例外修正 実装計画レビュー結果

## 1. 総合評価
実装計画書（`docs/wip/invisible-characters-fix/implementation_plan.md`）に記載された修正方針およびロジックは妥当であり、この方針で実装作業を進めて問題ありません。

- **`invisibleCharactersPlugin` の修正**: 可視範囲 `[from, to]` 内に限定した装飾追加ロジックにより、CodeMirror 6 の line gap 機構による範囲分割時でも `RangeSetBuilder` の位置昇順制約が守られ、`Ranges must be added sorted` 例外が発生しなくなります。
- **`indentGuidesPlugin` の修正**: `line.from >= from` ガードを追加することで、同一行が複数区間に分割された場合の Widget 二重追加を防止します。

---

## 2. 実装計画書へのフィードバック・推奨改善事項

### (1) 不具合発生条件の補足（記述の正確化）
CodeMirror 6 (v6.43.9) の内部コード（`LG.Margin` / `LG.MarginWrap`）を解析した結果、以下の挙動が確認されました。計画書の記述を補足しておくとより正確になります。

- **折り返し ON 時でも発生可能性あり**:
  - 折り返し OFF（`LG.Margin = 2000`）では約 4,000 文字超の行で発生。
  - 折り返し ON（`LG.MarginWrap = 10000`）でも約 20,000 文字超の超長大行で非描画領域（line gap）が発生します。
- **カーソル・選択範囲周辺での区間分割**:
  - 非描画領域はカーソル位置（および選択範囲の端）を回避して分割されるため、長大行の途中にカーソルを置いてスクロールした場合も同一行内で複数の `visibleRanges` 区間に分かれます。

### (2) `RangeSetBuilder` の仕様表現の修正
- 「直前に追加した位置以上（厳密な昇順）」という表現は、「直前に追加した位置以上（同位置の追加は許可 / 非減少順）」と修正するとより正確です。

### (3) インデントガイド処理のパフォーマンス微最適化
- `indentGuidesPlugin` において、`line.from >= from` のチェックを `getLineIndentInfo` や `resolveBlankLineIndent`（前後最大 100 行の探索処理）の呼び出し前に実施することで、表示範囲外（画面外）となる行頭の無駄なインデント計算処理をスキップできます。

## 3. 検証手順の具体化案
実機確認の際は以下のパターンで検証を実施することを推奨します。

1. **折り返し OFF（Alt + Z）での長大行検証**:
   - 5,000 文字以上の行（半角スペース、全角スペース、タブを含む）を左右スクロールし、例外なく不可視文字が描画され続けること。
2. **折り返し ON での超長大行検証**:
   - 25,000 文字以上の行を上下スクロールし、描画崩れや例外が発生しないこと。
3. **カーソル配置・改行記号の表示検証**:
   - 長大行の末尾にカーソルを配置した状態でスクロールし、行末まで移動した際に改行記号（`↵`）が正しく表示されること。
4. **インデントガイド連動検証**:
   - インデントガイド（`Alt + I`）と不可視文字表示（`Alt + W`）を両方 ON にした状態で長大行をスクロールし、例外や表示の重複が発生しないこと。
