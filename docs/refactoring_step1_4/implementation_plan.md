# ステップ 1.4: `main.rs` の軽量化と結合テスト

## 目的
これまでのステップで主要なロジックは各モジュールに抽出されましたが、`main.rs` にはまだ初期化時の雑多な処理（コマンドライン引数の解析、Windows固有のテーマ適用処理など）が残っています。これらを適切に分離して `main.rs` をさらに軽量化し、一連のリファクタリングの最終段階として結合テストを実施します。

## 提案する変更内容

### 1. コマンドライン引数解析の抽出 (`src/cli.rs`)
`main.rs` の冒頭にある、引数からファイルパスを取得して絶対パスに変換し、ファイルの存在確認を行う処理（約20行）を別モジュールに抽出します。
- **[NEW]** `src/cli.rs` を作成し、`pub fn parse_launch_file_arg() -> Option<String>` を実装します。
- **[MODIFY]** `main.rs` では `let file_arg = cli::parse_launch_file_arg();` の1行で呼び出すようにします。

### 2. 初期テーマ適用ロジックの抽出 (`src/theme.rs` または `commands.rs` への統合)
`main.rs` の `setup` 内にある、Windows固有の DWM (Desktop Window Manager) API を呼び出してダークモードを適用する処理を抽出します。
- 現在 `commands.rs` に `apply_theme` コマンドが存在しているため、この中のロジックを共通関数化して `setup` からも呼び出せるようにするか、あるいは `theme::apply_to_window(window, is_dark)` のような独立した関数として `src/theme.rs` に切り出します。
- **提案**: 今回は `src/theme.rs` を新規作成し、OS依存のテーマ適用ロジックをカプセル化することを提案します。



## 検証プラン (結合テスト)
一連のリファクタリング（ステップ 1.1 〜 1.4）の総仕上げとして、各モジュールが連携して正しく動作するかを通しで確認します。
### 自動テスト
- `cargo check` および `cargo build` によるコンパイル検証。
### 手動検証（ユーザー依頼）
- **通常起動とテーマ設定**: アプリを起動し、設定されたテーマ（ライト/ダーク）が正しく適用されること。
- **引数付き起動**: ターミナルから `cargo run -- "ファイルパス"` を実行し、ファイルの内容が正しくロードされること。
- **単一インスタンス動作**: 起動中に別のターミナルから再度引数付きで起動した際、既存のウィンドウにフォーカスが移り、ファイルが開かれること。
