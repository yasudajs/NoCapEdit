## 1. システムアーキテクチャ概要

NoCapEdit は **Tauri** フレームワークを採用しており、バックエンド（Rust）とフロントエンド（Vite + CodeMirror 6 + Vanilla JS）が緊密に連携して動作するハイブリッドアーキテクチャです。

- **バックエンド (Rust)**:
  - ファイルI/O、プロセス管理、システムダイアログの呼び出し、ウィンドウ制御など、OSネイティブの機能へのアクセスを提供します。
  - セキュリティとパフォーマンスを担保するコアロジックを担います。
- **フロントエンド (Web技術 + CodeMirror 6)**:
  - Vite を用いた ES Modules バンドル構成を採用しています。
  - エディタのコアエンジンに **CodeMirror (v6)** を採用し、高度なテキスト編集、タブごとの独立した Undo/Redo 履歴、動的な設定変更、および検索・置換機能を提供します。
  - Rust 側で定義された Tauri Command を呼び出すことで、ネイティブ機能を利用します。

## 2. ディレクトリ構成とファイルの役割

### 2.1 バックエンド (`src/`)

バックエンドは、機能ごとにRustのモジュールとして分割されています。

- `main.rs`:
  - エントリポイントです。Tauri アプリケーションの初期化、プラグイン（`tauri-plugin-single-instance` による名前付きパイプ/UNIXドメインソケット多重起動制御）の登録、および各コマンドのバインディングを行います。
  - > [!NOTE]
  - > `tauri-plugin-single-instance` は Tauri v1 向けの crates.io パッケージが存在しないため、Git リポジトリの `v1` ブランチから直接参照しています（`Cargo.toml` 参照）。将来的に Tauri v2 へ移行する際は、crates.io に公開されている v2 向けのレジストリ版（`tauri-plugin-single-instance = "2"`）に切り替えてください。
- `commands.rs`:
  - フロントエンドから呼び出される Tauri コマンド群（ファイル保存、読み込み、ダイアログ表示など）を定義しています。フロントエンドとバックエンドの橋渡し役となります。
- `settings.rs`:
  - アプリケーションの設定情報（ホームフォルダやテーマなど）の永続化、読み書き処理を担当します。
- `theme.rs`:
  - Windows のネイティブ機能（DWM API）と連携し、OSのダーク/ライトテーマ設定の監視とウィンドウタイトルバー色への適用を行います。
- `cli.rs`:
  - コマンドライン引数のパース処理を担当し、初期起動時および多重起動時のファイル引数抽出を制御します。

---

### 2.2 フロントエンド (`src/frontend/`)

フロントエンドは Vite でビルドされ、保守性を高めるため役割ごとにサブディレクトリに分割されています。

#### ルート・エントリポイント
- `index.html`: メインエディタ画面の HTML。
- `help.html`: F1キーで開くショートカット一覧・ヘルプ画面の HTML。
- `style.css`: アプリ全体の基本スタイルおよび CSS 変数定義。
- `i18n.js`: 多言語対応（i18n）テキストの一元管理辞書および翻訳関数。
- `js/main.js`: メイン画面のエントリポイント。DOMおよび各モジュールの初期化とイベント結合。
- `js/help.js`: ヘルプ画面のエントリポイント。テーマ同期やブラウザ起動イベントの制御。

#### `js/core/` (ビジネスロジック・状態管理)
UIのDOM操作は行わず、データの管理やバックエンド通信を担うモジュール群です。

- `state.js`: アプリケーションのグローバル状態（アクティブタブ、設定値、UI要素キャッシュなど）を管理します。
- `fileSystem.js`: ファイルの遅延生成、自動保存/手動保存、外部ファイル読み込み、終了前保存、バイナリ/サイズ上限ガードなどを担当します。
- `settingsManager.js`: アプリケーション設定のロードと保存の管理を行います。
- `tauri.js`: Tauri API の呼び出しを抽象化し、フロントエンドの他モジュールに提供するラッパーです。
- `updater.js`: アプリのアップデート確認ロジックを管理します。

#### `js/ui/` (エディタ制御・UI描画・イベント)
ユーザーとのインタラクションや画面の描画を担うモジュール群です。

- `codemirror.js`:
  - CodeMirror (v6) のコア管理モジュールです。`EditorView` / `EditorState` の初期化、テキスト取得/設定、選択範囲/メトリクス算出、動的設定変更（Compartment）、コマンドキーマップ、検索拡張、テーマ統合を一元管理します。
- `editor.js`:
  - エディタ周辺のUI制御（フォントサイズ/行間変更、ズームイン/アウト、メトリクス表示更新、テキスト変更同期など）を担当します。
- `tabs.js`:
  - タブの生成、切り替え、閉じる処理、および各タブごとの `EditorState`（編集履歴・カーソル位置・折り返し設定）の管理を行います。
- `settings.js`:
  - 設定ドック（右サイドパネル）のUI構築、設定項目のキーボードナビゲーション、および設定変更の即時反映を担当します。
- `theme.js`:
  - テーマ（ダーク / ソフトダーク / ライト）の適用や CSS 変数、システムフォント一覧の取得を行います。
- `shortcuts.js`:
  - グローバルキーボードショートカット（タブ切り替え、保存、新規タブ、終了、ズーム等）を捕捉・ディスパッチします。
- `dialogs.js`:
  - 各種モーダルダイアログ（エラー、確認など）の表示制御を行います。
- `updaterUI.js`:
  - アップデート通知バナーのUI表示を担当します。

#### `js/utils/` (汎用ヘルパー)
- `helpers.js`: 特定のドメインに依存しない汎用的なユーティリティ関数を提供します。

---

### 2.3 アセット・インストーラー (`icons/`, `nsis/`)

- `icons/`:
  - `icon.ico`, `icon.png`: アプリケーション本体（実行ファイル、タスクバー、スタートメニュー等）用の丸型アプリアイコン。
  - `document.ico`, `document.png`: NoCapEdit に関連付けられたファイル（`.txt`, `.nctx`, `.csv`, `.py` 等）専用のドキュメントアイコン。
- `nsis/`:
  - `installer.nsi`: Windows用インストーラー（NSIS）スクリプト。ファイルの配置、レジストリ登録（ファイル関連付け・右クリックメニュー登録）、アンインストール処理を制御します。

## 3. 実装方針と設計詳細

### 3.1 エディタアーキテクチャ (CodeMirror v6)

NoCapEdit では、従来の HTML `<textarea>` から **CodeMirror (v6)** へエディタエンジンを刷新しました。

1. **タブごとの独立した `EditorState` 保持**:
   - 各タブオブジェクト（`tabs.js`）は、ドキュメント内容、選択範囲、カーソル位置、および **Undo/Redo 履歴（`history`）** を含む CodeMirror の `EditorState` を直接保持します。
   - タブ切り替え時には `editorView.setState(tab.editorState)` を実行することで、タブ間の履歴混ざりを防ぎ、完全独立した編集体験を提供します。
2. **Compartment による動的設定制御**:
   - `wrapCompartment`（折り返し）、`indentCompartment`（インデント幅）、`themeCompartment`（テーマ）を導入しています。
   - エディタインスタンスを破棄・再生成することなく、実行時に `editorView.dispatch({ effects: ... })` で瞬時に設定を再構成します。
3. **公式拡張の統合**:
   - `@codemirror/commands`: 行の上下移動（`Alt + ↑/↓`）、行複製（`Alt + Shift + ↑/↓`）、行削除（`Alt + Shift + K`）、インデント（`Tab` / `Shift + Tab`）を統合。
   - `@codemirror/search`: エディタ上部の検索・置換パネル（`search({ top: true })`）および選択単語の自動ハイライト（`highlightSelectionMatches`）を統合。

---

### 3.2 設定値・定数の一元管理方針（ハイブリッドアプローチ）

アプリケーション全体のマジックナンバーや設定値を一元管理し、保守性を高めるために以下の役割分担（ハイブリッドアプローチ）を採用しています。

- **基本設定・振る舞い（Rust側で管理）**:
  - アプリケーションの基本定数（デフォルトの保存先パス、初期テーマ設定、ファイル拡張子、ウィンドウのデフォルトサイズなど）は、Rust側の設定モジュール（`settings.rs` 等）を「真なる情報源（Single Source of Truth）」として一元管理し、フロントエンドは起動時にTauriのAPI経由で値を取得します。
- **デザイン・UI設定（CSS変数で管理）**:
  - フォントファミリの定義文字列やフォントサイズ、行間、テーマカラーなどの描画に関する値は `style.css` の `:root` に集約し、JavaScriptからはCSS変数を書き換えることで外観を変更します。
- **フロントエンド固有のロジック（JSで管理）**:
  - オートセーブのデバウンス遅延時間（3000ms）やDOM要素のIDなど、OSやバックエンドに無関係なブラウザ固有の定数は、JS側の定数定義（または各モジュール）に集約します。

---

### 3.3 多言語対応 (i18n)

将来的な多言語化に備え、フロントエンドのUIに表示するテキスト（エラーメッセージやダイアログの文言など）は、コード内に直接ハードコードしません。

- **一元管理**: 表示テキストは `src/frontend/i18n.js` で一元的に定義し管理します。
- **階層化キー**: キー名はドット区切りの階層表現（例: `tabs.error.noHomeFolder`）を使用し、用途やコンテキストを明確にします。
- **呼び出し**: JSコードからは翻訳関数 `t('キー名')` を経由してテキストを取得し、HTML側では `data-i18n` 属性を用いて自動適用します。

---

### 3.4 ウィンドウ表示制御（起動時チラつき防止）

アプリケーション起動時にUIの描画が完了する前にウィンドウが表示されることによる、画面のガタつきやチラつき（Flash of Unstyled Content: FOUC）を防ぐため、以下のフローでウィンドウを表示します。

1. **初期非表示 (`visible: false`)**:
   - `tauri.conf.json` の設定により、OSからネイティブウィンドウを作成した直後は、ウィンドウを非表示のままバックグラウンドで維持します。
2. **初期化処理の実行**:
   - フロントエンド（JavaScript）側で、設定のロード、初期テーマの適用、および CodeMirror エディタ・初期タブのレンダリングを行います。
3. **描画完了後の表示 (`show`)**:
   - UIの描画が完全に整ったタイミングで、フロントエンドから Tauri のウィンドウ表示 API (`appWindow.show()`) を呼び出し、初めてメインウィンドウを表示させます。

---

### 3.5 キーボードショートカットの実装方針

キーボードショートカット（Ctrl+S, Ctrl+T, Ctrl+Tab など）のイベント捕捉は、**Tauri（Rust）側の GlobalShortcut 機能などを使用せず、フロントエンド（JavaScript）側で一元管理**します。

- **エディタ操作系キー**:
  - `Tab`, `Alt + ↑/↓`, `Alt + Shift + ↑/↓`, `Alt + Shift + K`, `F5` などのエディタ固有の操作は、CodeMirror のキーマップ（`keymap.of(...)`）で直接ネイティブ処理します。
- **アプリケーション操作系キー**:
  - `Ctrl + Tab`, `Ctrl + S`, `Ctrl + T`, `Ctrl + W`, `Ctrl + ,`, `F1`, `Ctrl + Q` などのグローバル操作は、`src/frontend/js/ui/shortcuts.js` 内の `window.addEventListener('keydown', ...)` で捕捉し、対応するロジックを呼び出します。

---

### 3.6 単一ウィンドウ動作（シングルインスタンス）とプロセス間通信

NoCapEdit は、多重起動を防止し常に単一のメインウィンドウで軽快に動作する設計を採用しています。

- **OSネイティブIPCによる制御**:
  - Tauri 公式プラグイン `tauri-plugin-single-instance` を採用し、OSネイティブのプロセス間通信（Windows: 名前付きパイプ、macOS/Linux: UNIXドメインソケット）によって安全に制御します。TCPポートを使用しないため、セキュリティ警告やポート競合は発生しません。
- **起動引数の通知フロー**:
  - すでにアプリが起動している状態で、エクスプローラーでのダブルクリックや「プログラムから開く」、コンテキストメニューから別プロセスで起動された場合、新規プロセスは起動引数のファイルパスを既存プロセスに通知して即座に終了します。
  - 既存ウィンドウは通知されたファイルパスを受け取り、新規タブとして開いてアクティブ化します。また、最小化状態や背後にある場合は最前面にウィンドウを復元します。

### 3.7 ファイル専用アイコンおよび OS 関連付け設計（NSIS連携）

NoCapEdit では、アプリケーションアイコンと関連付けファイル用アイコンを明確に分離し、Windows エクスプローラー上での視認性と親和性を最適化しています。

- **アイコンの二重構造**:
  - **アプリアイコン (`icon.ico`)**: 実行ファイル本体、デスクトップショートカット、タスクバー等で使用される丸型ブランドロゴ。
  - **ドキュメントアイコン (`document.ico`)**: NoCapEdit に関連付けられたファイル専用。デスクトップ等での大表示（角折れ用紙＋罫線＋丸ロゴ）と、エクスプローラー詳細表示等での小サイズ特化デザイン（用紙上に赤丸ロゴを大きくオーバーレイさせる WPS スタイル）を1つのマルチサイズ ICO（16px〜256px の全8解像度、32bpp RGBA）にパックしています。
- **NSISインストーラーによるレジストリ連携**:
  - `Software\Classes\Applications\NoCapEdit.exe\DefaultIcon` に `document.ico` を登録し、「常にこのアプリを使って開く」で選択されたすべての拡張子に専用アイコンを自動適用します。
  - 共通 ProgID（`Software\Classes\NoCapEdit.Document`）を定義し、主要なテキスト・コード系拡張子を `SupportedTypes` および Windows の「既定のアプリ」（`Capabilities\FileAssociations`）に事前登録します。
  - アンインストール時には登録したレジストリを完全に削除し、`SHChangeNotify`（`SHCNE_ASSOCCHANGED`）を発行して Windows のアイコンキャッシュを確実に更新します。
