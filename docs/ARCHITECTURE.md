# アーキテクチャとファイル構成

NoCapEdit のシステムアーキテクチャ、ディレクトリ構造、および各ファイルの役割分担について定義します。

## 1. システムアーキテクチャ概要

NoCapEdit は **Tauri** フレームワークを採用しており、バックエンド（Rust）とフロントエンド（HTML/CSS/JavaScript）が連携して動作するハイブリッドアーキテクチャです。

- **バックエンド (Rust)**:
  - ファイルI/O、プロセス管理、システムダイアログの呼び出し、ウィンドウ管理など、OSネイティブの機能へのアクセスを提供します。
  - セキュリティとパフォーマンスを担保するコアロジックを担います。
- **フロントエンド (Web技術)**:
  - UIの描画、ユーザー入力のハンドリング、エディタ機能の提供を行います。
  - Rust 側で定義された Tauri Command を呼び出すことで、ネイティブ機能を利用します。

## 2. ディレクトリ構成とファイルの役割

ソースコードは主に `src/` 配下に配置され、フロントエンドの資産は `src/dist/` 配下に格納されています。

### 2.1 バックエンド (`src/`)

バックエンドは、機能ごとにRustのモジュールとして分割されています。

- `main.rs`: 
  - エントリポイントです。Tauri アプリケーションの初期化、プラグイン（`tauri-plugin-single-instance` 等）の登録、および各コマンドのバインディングを行います。
- `commands.rs`: 
  - フロントエンドから呼び出される Tauri コマンド群（ファイル保存、読み込み、ダイアログ表示など）を定義しています。フロントエンドとバックエンドの橋渡し役となります。
- `settings.rs`: 
  - アプリケーションの設定情報（ホームフォルダやテーマなど）の永続化、読み書き処理を担当します。
- `instance.rs`: 
  - アプリケーションの多重起動防止や、別インスタンスからの引数受け取りなどのプロセス通信を管理します。
- `theme.rs`: 
  - Windows のネイティブ機能と連携し、OSのダーク/ライトテーマ設定の監視とウィンドウへの適用を行います。
- `cli.rs`: 
  - コマンドライン引数のパース処理を担当し、初期起動時の動作を制御します。

### 2.2 フロントエンド (`src/dist/js/`)

保守性を高めるため、JavaScriptのコードは役割ごとにサブディレクトリに分割されています。

#### `core/` (ビジネスロジック・状態管理)
UIのDOM操作は行わず、データの管理やバックエンド通信を担うモジュール群です。

- `state.js`: アプリケーションの現在の状態（アクティブなタブ、エディタの内容など）を管理します。
- `fileSystem.js`: ファイルの読み書き要求の制御や、保存状態の管理を行います。
- `settingsManager.js`: アプリケーション設定のロードと保存の管理を行います。
- `tauri.js`: Tauri API の呼び出しを抽象化し、フロントエンドの他モジュールに提供するラッパーです。
- `updater.js`: アプリのアップデート確認ロジックを管理します。

#### `ui/` (DOM操作・イベント・見た目の制御)
ユーザーとのインタラクションや画面の描画を担うモジュール群です。

- `tabs.js`: タブの生成、切り替え、閉じる処理など、タブUI全般のDOM操作とイベント制御を行います。
- `editor.js`: テキストエリア（エディタ部分）の制御や、入力イベントのハンドリングを行います。
- `settings.js`: 設定ダイアログのUI構築とイベント処理を担当します。
- `theme.js`: フロントエンド側におけるテーマ（ダーク/ライト）の適用やCSS変数の制御を行います。
- `shortcuts.js`: キーボードショートカットのイベントリスナーを登録し、対応するアクションを発火させます。
- `dialogs.js`: フロントエンド側の各種モーダルダイアログの表示制御を行います。
- `updaterUI.js`: アップデート関連のUI表示を担当します。

#### `utils/` (汎用ヘルパー)
- `helpers.js`: 特定のドメインに依存しない、汎用的なユーティリティ関数を提供します。

#### エントリポイント
- `main.js`: フロントエンドのエントリポイントです。DOMの読み込み完了を待機し、`core` や `ui` の各モジュールを初期化してシステム全体を結合します。

## 3. 実装方針と設計詳細

### 3.1 多言語対応 (i18n)

将来的な多言語化に備え、フロントエンドのUIに表示するテキスト（エラーメッセージやダイアログの文言など）は、コード内に直接ハードコードしません。

- **一元管理**: 表示テキストは `src/dist/i18n.js` で一元的に定義し管理します。
- **階層化キー**: キー名はドット区切りの階層表現（例: `folder.delete.error_title`）を使用し、用途やコンテキストを明確にします。
- **呼び出し**: JSコードからは翻訳関数 `t('キー名')` を経由してテキストを取得し、UIに反映させます。

### 3.2 ウィンドウ表示制御（起動時ガタつき防止）

アプリケーション起動時にUIの描画が完了する前にウィンドウが表示されることによる、画面のガタつきやチラつき（Flash of Unstyled Content: FOUC）を防ぐため、以下のフローでウィンドウを表示します。

1. **初期非表示 (`visible: false`)**:
   - `tauri.conf.json` の設定により、OSからネイティブウィンドウを作成した直後は、ウィンドウを非表示のままバックグラウンドで維持します。
2. **初期化処理の実行**:
   - フロントエンド（JavaScript）側で、設定のロード、初期テーマの適用、および初期タブのレンダリングを行います。
3. **描画完了後の表示 (`show`)**:
   - UIの描画が完全に整ったタイミングで、フロントエンドから Tauri のウィンドウ表示 API (`appWindow.show()`) を呼び出し、初めてメインウィンドウを表示させます。

### 3.3 キーボードショートカットの実装方針

キーボードショートカット（Ctrl+S, Ctrl+T, Ctrl+Tab など）のイベント捕捉は、**Tauri（Rust）側の GlobalShortcut 機能などを使用せず、原則としてフロントエンド（JavaScript）側で一元管理**します。

- **理由**: アプリがバックグラウンドにいる時でも反応してしまうグローバルショートカットの副作用を避けるため。また、タブ操作やエディタのUI状態に依存するショートカットが多いため、フロントエンドで直接イベント（`keydown`）を捕捉・処理する方が自然で安全なためです。
- **実装箇所**: `src/dist/js/ui/shortcuts.js` 内の `window.addEventListener('keydown', ...)` で一元的に捕捉し、ブラウザのデフォルト挙動（`e.preventDefault()`）を防いだ上で、対応するUIロジックを呼び出します。
