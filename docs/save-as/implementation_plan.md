# 実装計画書: 「名前をつけて保存」機能の追加

## 1. 概要
NoCapEdit に Windows 標準の「名前をつけて保存」ダイアログ（Common Item Dialog）を用いた名前をつけて保存（Save As）機能を追加する。
これにより、新規フォルダを作成して整理したり、別ドライブや任意の場所に自由なファイル名・拡張子でファイルを保存できるようにする。

---

## 2. 要件仕様

### 2.1 ショートカットキー & トリガー
- **ショートカットキー**: `Ctrl + Shift + S`
- **UIボタン**: 追加しない（既存の `Ctrl + S` や `Ctrl + O` と同様、ミニマルなUIを維持しキーボードショートカットで操作）

### 2.2 ダイアログの表示仕様
- **Windows 標準の「名前をつけて保存」ダイアログ（Tauri `saveDialog` API）** を使用
  - ユーザーはダイアログ上で「新しいフォルダー」を作成したり、別ドライブ（Dドライブ、外部USB等）を自由に選択可能
- **初期フォルダ（初期パス）**:
  - 新規タブ（ディスク上にファイル未作成）の場合: アプリ設定のホームフォルダ（例: `Documents/nce`）
  - すでに保存済みのファイルの場合: 対象ファイルが現在存在する親フォルダ
- **初期ファイル名**:
  - 新規タブの場合: その時点のタイムスタンプ形式のファイル名（例: `20261004_211500.nctx`）
  - 既存ファイルの場合: 現在のファイル名
- **ファイルの種類（拡張子フィルター）**:
  1. `NoCapEdit Text (*.nctx)`（デフォルト）
  2. `Text Files (*.txt)`
  3. `CSV Files (*.csv)`
  4. `すべてのファイル (*.*)`
  ※ダイアログ上で拡張子を変更して保存（例: `.nctx` から `.txt` や `.csv` などへ変更）可能。

### 2.3 保存後の動作・ライフサイクル
- **元ファイルの扱い（案A）**:
  - 元のファイルはそのままディスク上に保持（複製・別名保存）
  - 現在のタブの対象（`filePath`, `fileName`）を新しく保存したファイルへ切り替える
- **タブとエディタの状態更新**:
  - タブ名を保存したファイル名（例: `sample.txt`）に更新
  - 未保存フラグ（`isDirty`）を解除
  - 新しいファイル名・拡張子に基づいてシンタックスハイライト（言語サポート）を自動更新
  - ステータスバーに「[ファイル名] として保存しました」を通知表示
  - ダイアログ終了後、エディタにフォーカスを復帰
- **以降の保存挙動**:
  - 自動保存モード時: 以降の変更は新しく保存したファイルに対して自動保存される
  - 手動保存モード時: 以降の `Ctrl + S` は新しく保存したファイルに対して上書き保存される

### 2.4 マウスカーソルの最前面表示対策（ダイアログ背面隠れ防止）
- **課題**: フロントエンドの JS API（`dialog.save`）からダイアログを直接開くと、メインウィンドウとの親ウィンドウ関係（HWND）が明示されず、WebView2 とネイティブダイアログ間の描画競合によってマウスカーソルがダイアログの下（背面）に潜り込んでしまう。また、キー押下（keydown）直後にダイアログを開くと、OSの入力中カーソル非表示機能やWebView2のポインタキャプチャが解除されない問題が発生する。
- **対策仕様**:
  1. **Rust バックエンド側での親ウィンドウ紐付け (`show_save_dialog`)**:
     - `tauri::api::dialog::blocking::FileDialogBuilder::new().set_parent(&window)` を用いたカスタムコマンドを実装し、メインウィンドウの HWND を親ウィンドウとして確実に設定。OS のウィンドウ階層（モーダル親子関係）と Z-order を正常化し、マウスカーソルが確実に最前面に描画されるようにする。
  2. **フロントエンド側のキーイベント消化・フォーカス解放**:
     - `Ctrl + Shift + S` のキー押下直後に `setTimeout` で微小遅延を挟み、キー入力イベントの完了を待ってからダイアログを起動。エディタのポインタキャプチャを安全に解放した状態でダイアログを表示する。

## 3. 影響範囲・変更予定ファイル

### バックエンド (Rust)
1. `src/commands.rs`
   - 親ウィンドウを紐付けた保存ダイアログ表示コマンド `show_save_dialog` を追加
2. `src/main.rs`
   - `invoke_handler` に `commands::show_save_dialog` を登録

### フロントエンド
1. `src/frontend/js/core/fileSystem.js`
   - `saveTabAs(tab)` で `dialog.save` の代わりに Rust コマンド `show_save_dialog` を呼び出すように変更
   - `triggerManualSaveAs()` でキーイベント消化のための微小遅延・エディタフォーカス解放を追加
2. `src/frontend/js/ui/shortcuts.js`
   - `Ctrl + Shift + S` のキーイベント検知を追加し、`triggerManualSaveAs()` を実行
3. `src/frontend/i18n.js`
   - フィルター名、ステータス文言、ショートカット説明用の多言語テキスト追加
4. `src/frontend/help.html`
   - ショートカット一覧の「ファイル・タブ操作」に `Ctrl + Shift + S`（名前をつけて保存）を追記

### ドキュメント
1. `docs/SHORTCUTS.md`
   - キーボード操作一覧の「ファイル管理」または「テキスト編集」に `Ctrl + Shift + S` を追記
2. `docs/spec.md`（※フェーズ2開始時に更新）
   - セクション 4.5「ファイル保存と安全保護」に「名前をつけて保存 (`Ctrl + Shift + S`)」の仕様を追記

## 5. 検証手順
1. **新規未保存タブでの動作検証**:
   - テキストを入力し、`Ctrl + Shift + S` を押下。
   - ダイアログの初期フォルダがホームフォルダ、ファイル名がタイムスタンプ名、フィルターが `.nctx`（デフォルト）になっていることを確認。
   - フォルダを新規作成して移動し、拡張子を `.txt` に変更して保存。
   - 作成したフォルダ内に `.txt` で保存され、タブ名が更新され、エディタにフォーカスが戻ることを確認。
2. **自動保存済みタブ（タイムスタンプファイル）での動作検証**:
   - タイムスタンプ名で保存されたタブで `Ctrl + Shift + S` を押下。
   - 別名（例: `data.csv`）で保存。
   - 元のタイムスタンプファイルが残っており、現在のタブが `data.csv` に切り替わり、以降の編集が `data.csv` に保存されることを確認。
3. **別ドライブへの保存検証**:
   - Dドライブ等の別ドライブを選択して保存できることを確認。
4. **キャンセル時の挙動検証**:
   - `Ctrl + Shift + S` を押し、ダイアログで「キャンセル」を押した際に、タブやファイルが変更されずエディタに戻ることを確認。
5. **ヘルプ画面（`F1`）の表示検証**:
   - `F1` を押してショートカット一覧に「名前をつけて保存」が表示されることを確認。
