# ウォークスルー: 「名前をつけて保存」機能の追加 (v2.12.0)

## 1. 概要
NoCapEdit に Windows 標準の「名前をつけて保存」ダイアログ（Common Item Dialog）を用いた **名前をつけて保存 (`Ctrl + Shift + S`)** 機能を実装しました。
これにより、ユーザーはダイアログ内で新しいフォルダーを作成して整理したり、別ドライブや任意の保存場所に自由なファイル名・拡張子でファイルを保存できるようになりました。

---

## 2. 実装内容の詳細

### 2.1 ショートカットキー & 起動
- **キーボードショートカット**: `Ctrl + Shift + S`
- ミニマルなUIを維持するため、画面上の追加ボタンは配置せず、キーボード操作でシンプルに呼び出せます。

### 2.2 ダイアログの表示仕様
- **Windows 標準ダイアログ（Tauri `saveDialog` API）の活用**:
  - ダイアログ内で「新しいフォルダー」ボタンや右クリックメニューからフォルダを作成して格納可能
  - Dドライブや外付けストレージなど、別ドライブを自由に指定可能
- **初期フォルダと初期ファイル名**:
  - **新規（未保存）タブ**: アプリ設定のホームフォルダ（例: `Documents/nce`）を開き、ファイル名入力欄にその時点の日時タイムスタンプ（`yyyymmdd_hhmmss.nctx`）を初期値として自動セット
  - **既存ファイルタブ**: 対象ファイルが現在存在する親フォルダを開き、現在のファイル名を初期値としてセット
- **ファイルの種類（拡張子フィルター）**:
  1. `NoCapEdit Text (*.nctx)` （デフォルト）
  2. `Text Files (*.txt)`
  3. `CSV Files (*.csv)`
  4. `すべてのファイル (*.*)`
  ※ダイアログ上で拡張子を変更して保存（例: `.nctx` から `.txt` や `.csv` などへ変更）可能

### 2.3 保存後の動作・ライフサイクル
- **元ファイルの保持（案A）**:
  - すでにディスク上に存在していた元ファイルはそのまま保持（複製・別名保存）
  - 現在のタブの対象（`filePath`, `fileName`）を新しく保存したファイルへ切り替え
- **タブとエディタの状態更新**:
  - タブ表示名を保存後のファイル名に更新
  - 未保存フラグ（`isDirty`）を解除
  - 新しいファイルの拡張子に応じたシンタックスハイライト（言語サポート）を自動適用
  - ステータスバーに「`{fileName} として保存しました`」を通知表示
  - ダイアログ終了後、エディタにフォーカスを安全に復帰
- **以降の保存挙動**:
  - 自動保存モード時: 以降の変更は新しく保存したファイルに対して自動保存
  - 手動保存モード時: 以降の `Ctrl + S` は新しく保存したファイルに対して上書き保存

### 2.4 マウスカーソル非表示対策＆非同期化（根本解消）
- **親ウィンドウ（HWND）の明示的紐付け＆非同期実行**:
  - Rust 側に非同期コマンド `show_save_dialog` を実装し、`tauri::api::dialog::FileDialogBuilder::new().set_parent(&window)` および `tokio::sync::oneshot` チャンネルによる非同期コールバック処理を採用。メインスレッド（Windows の UI メッセージループ）をブロックせず「(応答なし)」フリーズを完全に防止しました。
- **Win32 `SetCursorPos` によるカーソル再表示の強制**:
  - Windows の「文字の入力中にポインターを非表示にする」OS機能により、キー入力時に消えたカーソルが別スレッドのダイアログ上で再表示されない問題に対し、Win32 API（`GetCursorPos` / `SetCursorPos`）を用いて現在座標への再セットを実行。OSにマウス移動と同等のウェイクアップイベントを認識させ、入力中非表示状態を強制解除してダイアログ上でのカーソル可視化を確実に保証しました。
- **フロントエンド呼び出しの整理**:
  - `triggerManualSaveAs` の不要な blur/遅延処理を整理し、自然かつクリーンな非同期実行フローに改修しました。
