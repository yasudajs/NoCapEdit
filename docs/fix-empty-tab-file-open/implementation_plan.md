# 初期空タブへのファイルドロップ/オープン時の内容非表示バグ修正 実装計画書

## 1. 概要
NoCapEdit 起動直後の初期空タブ（未編集・ファイル未作成）に対してファイル（CSVや各種テキストファイル等）をドラッグ＆ドロップまたはファイル選択ダイアログから開いた際、タブ名やステータスバーは更新されるもののエディタ上のテキスト内容が表示されない（空のままになる）不具合を修正します。

---

## 2. 原因と修正方針

### 2.1 原因
- `fileSystem.js` の `openExistingFile` において、初期空タブ（`firstTab`）を再利用する際に `editorState` を新しく生成してセットした後、`switchTab(firstTab.id)` を呼び出していました。
- `switchTab(tabId)` の冒頭では「現在アクティブなタブのエディタ内容を吸い出して退避・保存する処理」が実行されます。
- 切り替え前と切り替え先のタブIDが同一（`firstTab.id`）であったため、画面上に残っていた古い空のエディタ状態（`doc: ""`）によって、新しくセットした `firstTab.editorState` および `firstTab.content` が空文字で上書きされてしまっていました。

### 2.2 修正方針
1. **`tabs.js` の `switchTab(tabId)` における同一タブガード**:
   - `if (appState.currentTab && appState.currentTab !== tabId)` のように、異なるタブへ切り替える場合のみ直前タブのエディタ状態退避・保存を実行するようガードを追加。
2. **`fileSystem.js` の `openExistingFile` における初期空タブ置換処理の確実化**:
   - 初期空タブ置換時に、新しく生成した `editorState` を `setEditorState(firstTab.editorState)` でエディタへ直接反映し、メトリクス更新やフォーカス設定を確実に実行。

## 4. 検証手順

1. **起動直後の初期空タブへの D&D 検証**:
   - NoCapEdit を起動し、何も入力していない初期空タブの状態で CSV ファイル（または任意のテキストファイル）をドラッグ＆ドロップ。
   - エディタ上にファイルの内容が即座に表示され、文字数メトリクスおよびシンタックスハイライトが正常に反映されることを確認。
2. **起動直後の初期空タブでの `Ctrl + O` 検証**:
   - 初期空タブの状態で `Ctrl + O` からファイルを開き、内容が正常に表示されることを確認。
3. **2枚目以降のファイルオープン検証**:
   - 続けて別のファイルを D&D または `Ctrl + O` で開き、新規タブとして正常に内容が表示されることを確認。
