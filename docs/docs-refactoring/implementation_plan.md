# ドキュメント整理・再編集 実装計画書 (implementation_plan.md)

`docs/spec.md`（製品仕様書）および `docs/ARCHITECTURE.md`（アーキテクチャ設計書）について、内容の肥大化・重複・記述粒度のバラつきを解消し、今後のメンテナンス性を高めるための整理・再編集を実施します。

## 1. 目的と基本方針

### 1.1 目的
- **仕様書 (`spec.md`) の純化**: ユーザー視点・製品要件（機能・UI・挙動）に焦点を当て、過密になった章立ての分割や、不要・古い記述の解消を行う。
- **アーキテクチャ書 (`ARCHITECTURE.md`) の充実**: 内部実装詳細（定数管理方針、アイコン・レジストリ連携、プロセス間通信など）を集約し、開発者がシステム全体構造を把握しやすい状態にする。
- **ドキュメント間の適切な境界設定**: 仕様（What/Why）と内部構造（How）の重複をなくし、相互リンクによって追従性を向上させる。

---

## 2. 主な改定内容

### 2.1 `docs/spec.md` の改定
1. **章立ての論理的再編（過密セクションの分割）**:
   - 現在80行以上に及ぶ「4.4 テキスト編集と保存仕様」を以下の独立した項に分割・整理：
     - **4.4 テキスト編集機能**: 文字コード・改行、行操作、タイムスタンプ挿入、検索・置換、IMEインライン入力など
     - **4.5 ファイル保存と安全保護**: 自動保存/手動保存モード、安全保存方式（一時ファイル置換）、空ファイル自動クリーンアップ、保存失敗リカバリ
     - **4.6 ファイルオープンと読み込み安全ガード**: ファイルを開く（ダイアログ、D&D、右クリックメニュー）、初期空タブ置換、サイズ上限/バイナリガード、シンタックスハイライト
   - これに伴い、以降の項番を「4.7 画面表示」「4.8 ファイル関連付けと専用アイコン、シングルインスタンス」「4.9 ユーザー設定と永続化」「4.10 自動アップデートチェック」「4.11 ショートカット・ヘルプ・メニュー制限」に整理。
2. **アーキテクチャ記述の移管**:
   - 旧 4.8節「設定値・定数の一元管理（ハイブリッドアプローチ）」は完全な内部設計方針のため `ARCHITECTURE.md` へ移管し、`spec.md` からは削除。
   - 旧 4.6節の「ファイル専用アイコン」やレジストリ登録の微細な実装詳細（画像ピクセル仕様や内部レジストリキー詳細）を簡潔な機能仕様にまとめ、技術的背景は `ARCHITECTURE.md` に委ねる。
3. **記述の矛盾・古くなった情報の修正**:
   - 「5.1 将来の拡張候補」に残っていた「既存ファイルを開く機能」を削除（4.6節ですでに実装済みのため）。
   - 11行目の `history.md` へのリンクに別環境の絶対パス（`c:/work/...`）が含まれているのを相対リンクに修正。
   - 4.10（新4.11）のショートカット無効化における `F5` の記述を整理（`F5` はタイムスタンプ挿入に割り当てられているため、ブラウザリロードとしての無効化との関係性を明確化）。

### 2.2 `docs/ARCHITECTURE.md` の改定
1. **設定値・定数の一元管理方針の集約**:
   - `spec.md` から移管した「Rust / CSS / JS の役割分担（ハイブリッドアプローチ）」を第3章（実装方針と設計詳細）に統合。
2. **OS連携・配布関連のアーキテクチャ追記**:
   - シングルインスタンス（名前付きパイプによるプロセス間通信）の連携フロー。
   - インストーラー（NSIS）によるファイル関連付け（ProgID、SupportedTypes、Capabilities）と専用マルチサイズアイコン（`document.ico`）の設計意図を整理して明記。
3. **最新のディレクトリ・ファイル構成への同期**:
   - 現在のコードベース（モジュール分割や設定管理）の最新状況を反映し、全体の目次・見出し構成を統一。

## 3. 実装手順（フェーズ2）

ユーザーの承認後に以下の手順で実施します。
1. 作業用ブランチ `feature/docs-refactoring` を作成。
2. WIPドキュメントを `docs/wip/docs-refactoring/` から `docs/docs-refactoring/` へ移動。
3. バージョン番号のインクリメント（`0.2.21` → `0.2.22`）※ルール対象の5ファイルを更新。
4. `docs/ARCHITECTURE.md` の編集・リファクタリング。
5. `docs/spec.md` の編集・リファクタリング。
6. マークダウンリンクや整合性の検証。
7. ウォークスルー（`docs/docs-refactoring/walkthrough.md`）の作成および `docs/history.md` への更新履歴追記。
8. コミット＆プッシュし、ユーザーへ報告。
