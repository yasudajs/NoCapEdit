# 実装計画書: 自動インデントのVS Code準拠化および全角スペース不具合修正

## 1. 概要
NoCapEditにおいて、行頭に全角スペースが存在する状態でEnterキーにより改行した際、次行に全角スペースではなく半角スペースが挿入されてしまう不具合を修正します。
また、自動インデントの挙動をVS Codeと同等にし、当該行の行頭にある空白文字（全角スペース、半角スペース、タブ）の状態をそのまま次の行に反映（引き継ぎ）するように改修します。

---

## 2. 不具合の原因
CodeMirror 6 のデフォルトキーマップ（`defaultKeymap`）に含まれる `insertNewlineAndIndent` コマンドは、改行時に直前の行頭の空白（正規表現 `^\s*`）を取得したあと、`state.countColumn` によりカラム幅（数値）へと変換し、`indentString(state, cols)` 関数によってエディタのインデント設定（`indentUnit` や `tabSize`）に従って半角スペースやタブを**ゼロから再構築（合成）**して挿入する仕様となっています。

- タブサイズ 4（デフォルト）の場合、全角スペース1文字は幅 1 カラムと換算されるため、タブ幅（4）に満たず、半角スペース 1 文字（`" "`）に変換されて挿入されていました。
- タブの場合は幅 4 と換算され、再構築時にもタブ 1 文字が生成されていたため、正常に動作しているように見えていました。

---

## 3. 解決策・改修内容

CodeMirror 標準の `insertNewlineAndIndent` に依存せず、VS Code 準拠のカスタム改行・自動インデントコマンド `customInsertNewlineAndIndent` を作成し、`customEditorKeymap` の Enter キーに登録して標準コマンドを上書きします。

### 仕様・挙動詳細（VS Code準拠）
1. **行頭インデントの完全保持**:
   - 行頭の空白（正規表現 `/^[ \t\u3000]*/`）を取得し、文字種や文字幅の変換を行わず、そのままの文字列（`baseIndent`）を次行の先頭へ反映します。
   - 全角スペース、半角スペース、タブの混在パターンもそのまま忠実に維持されます。
2. **カーソル位置に応じた適切な改行処理**:
   - **インデントの後ろ・行末・テキスト途中での改行**:
     前行の行頭インデント文字列（`baseIndent`）をそのまま次行の先頭に挿入し、カーソルはインデントの直後に配置します。
   - **空白文字のみの行での改行**:
     空白文字のみの行末で改行した場合も、そのインデントをそのまま次行へ引き継ぎます。
   - **行の最先頭（行頭）での改行**:
     インデントの手前（行の先頭）で改行した場合は、上に空行を挿入し、既存のインデントは次行のテキストに残します。
   - **インデント文字の途中での改行**:
     インデントの文字間で改行した場合は、カーソル位置で分割して改行します。
   - **括弧ペア（`{}`、`[]`、`()`）の間での改行**:
     前行のインデントをベースに、括弧展開（中間行のインデント追加＋次行に閉じ括弧）を行います。
3. **Undo/Redo・複数選択（マルチカーソル）対応**:
   - CodeMirror の `state.changeByRange` を利用し、1つのトランザクション（単一のUndo履歴）として処理します。
   - 複数カーソルやテキスト選択状態でのEnter入力にも安全に対応します。

## 6. 検証・テスト計画
1. **全角スペースの改行テスト**:
   - `　aiueo` の末尾でEnterキーを押下 → 次行先頭に全角スペース `　` が挿入されることを確認。
   - `　　aiueo`（全角2個）の末尾でEnterキーを押下 → 次行先頭に全角スペース 2 個が挿入されることを確認。
2. **タブの改行テスト**:
   - `\tkakikukeko` の末尾でEnterキーを押下 → 次行先頭にタブ `\t` が挿入されることを確認。
3. **半角スペースの改行テスト**:
   - `  text`（半角2個）、`    text`（半角4個）でEnterキーを押下 → 半角スペースの個数がそのまま次行に維持されることを確認（タブ等に変換されないこと）。
4. **混在インデントの改行テスト**:
   - `　\t  mix` でEnterキーを押下 → `　\t  ` がそのまま次行に維持されることを確認。
5. **カーソル位置ごとの挙動テスト**:
   - テキスト途中（`　aiu|eo`）での改行 → 1行目 `　aiu`、2行目 `　eo` になりカーソルが `eo` の直前にあることを確認。
   - 行頭（`|　aiueo`）での改行 → 1行目空行、2行目 `　aiueo` になることを確認。
   - インデント文字の途中（`[全角1]|[全角2]aiueo`）での改行 → 1行目 `[全角1]`、2行目 `[全角2]aiueo` になることを確認。
   - 空白のみの行（`　　|`）での改行 → 次行にも `　　` が引き継がれることを確認。
6. **既存機能への影響確認**:
   - 日本語IME入力（変換確定時のEnterで改行されないこと）の確認。
   - Undo/Redo（Ctrl+Z / Ctrl+Y）の正常動作確認。
   - ビルド確認（`npm run build` および `cargo check`）。
