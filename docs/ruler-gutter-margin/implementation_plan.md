# 実装計画書: 行数表示時の境界線余白削除およびルーラー位置整合化

## 1. 概要
NoCapEditにおいて、行番号を表示した際にエディタ本文の左側に `16px` の余白が存在するため、ルーラー表示時の目盛り「0」の位置（およびルーラースペーサーの右境界線）と、エディタの行数境界線（ガターの右境界縦線）に `16px` のズレ（段差）が生じていました。
本改修では、行番号非表示時は従来どおり左側余白（16px）を維持しつつ、行番号表示時は境界線との余白を無し（0px）に変更することで、ルーラーの目盛り「0」および境界線が行数境界線と完全に一直線に揃うように改善します。

---

## 2. 背景と目的
- **現状の課題**:
  - 行番号表示時、CodeMirrorの `.cm-line` に `padding: 0 16px` が適用されているため、行番号ガターの境界線の右側に 16px の空白余白が存在する。
  - ルーラーのスペーサー幅はエディタのテキスト開始位置（1文字目左端）に合わせて設定されるため、ルーラーのスペーサー境界線（縦線）と行番号境界線（縦線）が 16px 食い違って段差になっていた。
  - また、選択行ハイライト等の背景も境界線との間に 16px の白抜けが発生していた。
- **改善目的**:
  - 行数非表示時はテキストが画面端に密着しないよう、従来通り左側余白（16px）を維持する。
  - 行数表示時は境界線との余白を 0px にし、ルーラーの「0」目盛り・スペーサー境界線・行数境界線を上から下まで一直線に揃え、自然で美しいエディタUIを実現する。

---

## 3. 仕様変更の詳細

| 状態 | 左側余白（padding-left） | ルーラースペーサー幅 | ルーラー「0」と境界線の関係 |
|---|---|---|---|
| **行数非表示時** | `16px`（従来通り維持） | `16px` | エディタ左端から16pxの位置からルーラー目盛り開始 |
| **行数表示時** | **`0px`（無しに変更）** | **ガター幅そのもの** | **行数境界線とルーラー目盛り「0」および境界線が一直線に一致** |

- 右側余白（`padding-right`）は、どちらの状態でも従来どおり `16px` を維持します。
- 行数表示時の選択行ハイライト（`.cm-selectionBackground` 等）も、行数境界線の直後から綺麗に描画されるようになります。

---

## 4. 影響範囲および変更対象ファイル

### ① `src/frontend/style.css`
- `.editor .cm-line` のスタイル定義を調整。
- デフォルト（行番号非表示）では `padding: 0 16px` を維持。
- 行番号表示時（`.editor.has-line-numbers .cm-line` または `.editor:has(.cm-gutters) .cm-line`）において、`padding: 0 16px 0 0`（左余白 0px）を適用。

### ② `src/frontend/js/ui/codemirror.js`
- CodeMirrorの基本テーマスタイルにおいて、行番号有効時の `.cm-line` の `padding-left` を 0 に設定。
- `updateLineNumbers(enable)` 時にエディタコンテナへ `.has-line-numbers` クラスをトグル付与（テーマCSSとの確実な連動）。

### ③ `src/frontend/js/ui/ruler.js`
- `getGutterOffset()` 内のフォールバック計算において、ガターが存在する（行番号表示中）場合の計算式を `gutters.offsetWidth + 16` から `gutters.offsetWidth`（余白なし）に更新。

## 5. 検証手順 (Verification Plan)

1. **行番号 ON / ルーラー ON 時の表示確認**:
   - 行数境界線（ガター右端の縦線）と、ルーラーのスペーサー境界線が完全に一直線に揃っていること。
   - ルーラーの「0」目盛りおよびカレットインジケータが行数境界線の直後に配置されていること。
   - テキストの先頭（1文字目）が行数境界線の直後から開始されること。
   - 行選択・範囲選択時のハイライトが行数境界線から途切れず描画されること。
2. **行番号 OFF / ルーラー ON 時の表示確認**:
   - 従来どおりエディタ左端から 16px の余白が維持されていること。
   - ルーラーの「0」目盛りもエディタ左端から 16px の位置から開始されること。
3. **動的切り替えの確認**:
   - 設定モーダルおよびショートカットキー（Alt+L 等）で行番号の ON/OFF を切り替えた際、余白およびルーラーのスペーサー幅が即座に正しく追従すること。
   - フォントサイズ変更、ズームイン/アウト時にもズレが発生しないこと。
4. **ビルド検証**:
   - `npm run build` または `cargo check` がエラーなく通過すること。
