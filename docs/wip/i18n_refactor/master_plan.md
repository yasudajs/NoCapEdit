# i18n リファクタリング マスタープラン

## 1. 目的と概要
NoCapEdit の将来的な多言語化（i18n）に向けて、現在フロントエンドの各 JavaScript ファイルや HTML にハードコードされている日本語文字列を、すべて `src/dist/i18n.js` に抽出・集約する。
抽出後の各テキストは、新たに導入したドット区切り（階層構造）のキー（例: `settings.general.title`）を用いて `window.t()` 関数経由で呼び出す仕組みへと完全に移行する。

## 2. 移行戦略と基本方針
- **ファイル単位での段階的移行**: 全体の一括置換は行わず、モジュール（ファイル）ごとに調査・抽出・動作確認を繰り返す安全なアプローチを採用する。
- **キー命名規則の徹底**: ドット区切りの名前空間を活用し、第一階層を「対象モジュール・画面名」、第二階層以降を「要素・機能名」として整理する。
  - 例: `settings.xxx`, `tabs.xxx`, `fs.xxx`, `dialog.xxx`
- **WIPフォルダでの計画管理**: 本マスタープランは長期的な移行作業を管理するため、クリーンアップ対象外となる `docs/wip/i18n_refactor/master_plan.md` に配置し、進捗に応じて更新し続ける。

## 3. 実施フェーズ（順番）

作業は、ユーザー目に触れるテキスト（UI）が多い箇所から順に、以下のフェーズに分けて実施する。

### [Phase 1] UIコンポーネントの移行 (`src/dist/js/ui/`)
UI構築や設定画面など、最も固定テキストが密集している層。
- [x] **Step 1.1**: `settings.js` （設定画面の各項目ラベル、説明文、ボタン名など）
- [x] **Step 1.2**: `tabs.js` （タブの右クリックコンテキストメニュー、未保存状態の表示テキストなど）
- [ ] **Step 1.3**: `editor.js` （エディタ領域関連の通知やプレースホルダーなど）

### [Phase 2] コアロジックの移行 (`src/dist/js/core/`)
ファイル操作やシステム連携に伴うエラー・通知メッセージ層。
- [ ] **Step 2.1**: `fileSystem.js` （保存・読み込み時のエラーダイアログ、成功通知など）
- [ ] **Step 2.2**: `tauri.js` （Tauri APIラッパー内で発生するシステムエラーの文言など）

### [Phase 3] メイン制御と静的HTMLの移行
アプリ初期化とベースとなる静的UIのテキスト。
- [ ] **Step 3.1**: `main.js` （初期化時のエラーメッセージ、グローバルなイベント通知など）
- [ ] **Step 3.2**: `index.html` （HTMLに直接記述されている設定モーダルの枠組みテキストなど）
  - *対応方針*: HTML内の固定テキストを削除し、アプリ起動時（`main.js` または各コンポーネント初期化時）に JS から `t()` を使って DOM 要素（`textContent` や `innerHTML`）にテキストを流し込む方式に変更する。

## 4. 進め方のルール
各Stepを実行する際は、以下のフローを遵守する。
1. 対象ファイル内のハードコード文字列をリストアップし、対応するドット区切りキーを設計する。
2. ユーザーとキー名・構造を合意（レビュー）する。
3. `i18n.js` の `DICT` にキーと日本語文字列を追加する。
4. 対象ファイル内の文字列を `t('...')` の呼び出しに書き換える。
5. アプリ上でテキストが正しく表示されることを動作確認する。
6. 作業用ドキュメント（ウォークスルー等）を作成し、コミット・プッシュして完了とする。
