# [リファクタリング] ステップ 3.1：アップデートチェックロジックの抽出 ウォークスルー

## 実装内容
リファクタリングマスタープランの「ステップ 3.1」に基づき、設定画面のUI制御を担う `ui/settings.js` から、アップデート通知に関する機能（API通信・バージョン比較および通知UIのDOM操作）を抽出し、新たなモジュール `core/updater.js` に分離しました。

- **バージョン更新**: `0.1.54` から `0.1.55` へバージョンアップしました (`Cargo.toml`, `tauri.conf.json`, `installer.nsi`)。
- **ロジックの分離**: `src/dist/js/ui/settings.js` の `checkNewVersion` 関数を削除し、`src/dist/js/core/updater.js` に新規作成しました。
- **インポートの変更**: `src/dist/js/main.js` にて、`checkNewVersion` のインポート元を `./core/updater.js` に変更しました。

## 動作確認結果
- Rustビルド（`cargo check`）が正常に完了し、コードの構文エラーや依存関係のエラーがないことを確認しました。
- 既存のロジックをそのまま移行しているため、アプリ起動時の裏側でのGitHub API通信およびアップデート通知機能（新しいバージョンが存在する場合のタイトルバー表示・下部リンク表示）がそのまま維持される設計となっています。
