# [リファクタリング] ステップ 3.3：テーマおよびフォント適用ロジックの抽出 ウォークスルー

## 実装内容
リファクタリングマスタープランの「ステップ 3.3」に基づき、UI層の「テーマ・フォント適用」の責任を `settings.js` から切り離しました。

- **バージョン更新**: `0.1.56` から `0.1.57` へバージョンアップしました (`Cargo.toml`, `tauri.conf.json`, `installer.nsi`)。
- **適用ロジックの抽出**: `src/dist/js/ui/theme.js` を作成し、純粋な適用処理 (`applyThemeUI`, `applyFontFamily`, `loadSystemFonts`) を集約しました。
- **UIイベントと適用処理の分離**:
  - `src/dist/js/ui/settings.js` から適用処理を削除し、イベントハンドラ (`onThemeChange`, `onFontFamilyChange`) のみを残しました。
  - ダイアログ操作のイベントハンドラは引き続き `settings.js` で受け付け、適用処理は `theme.js` を、保存処理は `settingsManager.js` を呼び出すように整理し、循環参照の根本原因を解消しました。
- **既存ファイルの整理**:
  - `src/dist/js/main.js` における適用処理のインポート元を `theme.js` に変更しました。

## 動作確認結果
- Rustビルド（`cargo check`）が正常に完了し、構文エラーや依存関係のエラーがないことを確認しました。
- UIのダイアログ制御、テーマとフォントの適用処理、そして設定の永続化管理という3つの関心事が完全に分離され、今後の機能拡張（新しい設定項目やテーマの追加）に耐えうるクリーンな設計となりました。
