# [WIP] ファイルツリー名前変更・新規作成時のインライン入力欄におけるマウス操作不具合の修正計画

## 概要

ファイルツリーで既存ファイル/フォルダの名前変更時（および新規作成時）に表示されるインライン入力欄（`<input class="tree-input">`）において、以下のマウス操作が行えない不具合を修正する計画です。

- **不具合現象**:
  1. 入力欄をクリックしてもマウスでのカーソル移動や範囲選択（ドラッグ選択）ができない。
  2. 入力欄の上で右クリックした際、文字列のコピー・切り取り・貼り付け・すべて選択といった操作（または標準コンテキストメニュー）が行えず、ファイルツリー全体のカスタムコンテキストメニューが表示されて入力欄が閉じてしまう。

---

## 原因分析

コードベース調査の結果、以下の4つの原因が複合して発生していることが判明しました。

1. **CSSの `user-select: none` の継承**:
   - `.tree-item` に `user-select: none;` が設定されており、子要素である `.tree-input` に `user-select: text;` が明示されていないため、テキスト選択が無効化されている。
2. **親要素 (`.tree-item`) の `draggable="true"` の影響**:
   - `.tree-item` 全体が HTML5 Drag and Drop の対象（`draggable="true"`）となっているため、入力欄の上でマウスドラッグを始めるとテキストの範囲選択ではなくアイテムのドラッグ操作（`dragstart`）が優先・トリガーされてしまう。
3. **右クリック (`contextmenu`) イベントのバブリングとカスタムメニュー発火**:
   - インライン入力欄 (`<input>`) 上で右クリックした際、`contextmenu` イベントが親の `.tree-item` にバブリングし、`selectItem` やアプリ独自の `showContextMenu` が実行される。
   - これによりブラウザ標準のコピー＆ペーストメニューが阻害され、さらにカスタムメニュー表示に伴って入力欄の `blur` イベントが発火し、編集が意図せず確定/キャンセルされる。
4. **マウスクリック・ダウライベントのバブリング**:
   - `<input>` 上での `mousedown` / `click` / `mouseup` イベントが親要素にバブリングし、親要素の選択切り替え処理やフォーカス処理と競合する。

---

## 修正方針案

### 1. CSSの修正 (`src/dist/style.css`)
`.tree-input` スタイルに明示的にテキスト選択を許可するプロパティを追加します。

```css
.tree-input {
    user-select: text;
    -webkit-user-select: text;
    /* ... 既存スタイル ... */
}
```

### 2. インライン入力欄へのイベント制御追加 (`src/dist/js/ui/sidebar.js`)
`startRenameInTree()` および `createNewItemInTree()` 内で生成される `<input class="tree-input">` に対して、以下のイベントハンドラを追加します。

- **マウス操作のバブリング防止**:
  `mousedown`, `mouseup`, `click`, `dblclick` イベントで `e.stopPropagation()` を実行し、親要素のドラッグ開始やフォーカス奪取、アイテム選択イベントを阻害防止する。
- **右クリック (`contextmenu`) の制御**:
  `contextmenu` イベントで `e.stopPropagation()` を実行し、親の `contextmenu` ハンドラ（アプリ独自のファイルツリーコンテキストメニュー表示）が動くのを防ぐ。これにより、入力欄上でブラウザ標準のテキストコンテキストメニュー（コピー、貼り付け等）が利用可能となる。
- **ドラッグ開始 (`dragstart`) の防止**:
  `dragstart` イベントで `e.preventDefault()` および `e.stopPropagation()` を実行し、入力欄選択時にアイテムのドラッグが開始されないようにする。

## 難易度および影響度評価

- **難易度**: **低** (変更箇所はCSSとJSの2ファイル・十数行程度。ロジックの複雑化は伴わない)
- **影響度**: **小（極めて限定的）** (`<input class="tree-input">` の内部操作に閉じているため、通常時のツリークリックやドラッグ＆ドロップなどの既存機能には影響しない)

---

## 実装時の留意点

- **右クリック時の `blur` 発火タイミグの動作検証**:
  入力欄上で右クリックしてブラウザ標準のテキストコンテキストメニュー（コピー・貼り付け等）を表示・操作した際、OS/ブラウザの仕様によっては入力欄の `blur` イベントが意図しないタイミングで発火し、入力欄が勝手に閉じたり確定されてしまわないか、実機環境で入念に動作検証を行う。

## 検証計画

### 手動テスト項目
1. **名前変更時のテキスト選択テスト**:
   - ファイルツリーの項目を右クリック ➔ 「名前を変更」を選択。
   - 入力欄内のテキストをマウスでドラッグして部分選択・全選択できるか確認。
   - クリックした位置に文字入力カーソルが移動するか確認。
2. **右クリック・コンテキストメニューおよびコピー＆ペーストテスト**:
   - 名前変更入力欄で右クリックした際、アプリ固有のツリーメニューが開かず、コピー・切り取り・貼り付けができるか確認。
   - キーボードショートカット (Ctrl+C, Ctrl+V, Ctrl+A) および右クリック操作での貼り付け確認。
   - 右クリックメニュー操作中に `blur` によって入力欄が不意に閉じたりしないか確認。
3. **新規作成インライン入力欄の確認**:
   - 「新規ファイル」「新規フォルダ」作成時も同様にマウス選択・コピーペーストが可能か確認。
