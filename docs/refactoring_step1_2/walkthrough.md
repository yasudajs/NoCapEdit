# ウォークスルー: ステップ 1.2 単一インスタンス制御ロジックの抽出

## 変更内容
1. **`src/instance.rs` の新規作成**
   - `main.rs` に存在していた単一ウィンドウ動作のための制御ロジック（ポート監視、重複起動の判定、別プロセスへのパス渡し）を `instance.rs` に抽出しました。
   - `SINGLE_INSTANCE_PORT`, `SINGLE_INSTANCE_HOST` などの定数も移動しました。
   - `main.rs` をシンプルにするため、重複起動判定とパス渡しをまとめた `check_primary_or_forward` 関数を新設しました。

2. **`src/main.rs` のリファクタリング**
   - 単一インスタンス制御のコードを削除し、`mod instance;` を追加しました。
   - 初期化時の判定を `if !instance::check_primary_or_forward(file_arg.as_ref()) { std::process::exit(0); }` に置き換えました。
   - `instance::start_instance_listener` を呼び出すように変更しました。
   - 依存しなくなったインポートを削除しました。

3. **ドキュメント・バージョンの更新**
   - バージョン番号を `0.1.50` にインクリメントしました（`Cargo.toml`, `tauri.conf.json`, `installer.nsi`, `DEVELOPMENT.md`）。

## テスト・検証結果
* `cargo check` を実行し、モジュール分割に伴うコンパイルエラーや警告がないことを確認しました。

## ユーザーへの確認事項
* モジュールの切り出しとビルドチェックは完了しました。
* 念のため、アプリを手動で起動していただき、以下の動作をご確認ください。
  1. 通常通り単一ウィンドウとして起動できること。
  2. 起動中に別のターミナルから `cargo run -- "C:\適当なパス\ファイル.txt"` などを実行した際、既存のウィンドウが最前面にフォーカスされ、そのファイルが開かれること。
  3. 重複して複数のウィンドウが起動しないこと。
